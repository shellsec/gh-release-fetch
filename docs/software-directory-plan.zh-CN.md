# 多平台软件导航与下载站规划

日期：2026-11-03。状态：规划草案，尚未修改页面或部署。

## 1. 产品定位

让用户按设备、用途找到合适工具，理解为什么需要它，再获取合适的稳定版本。

首页主张：**好用的工具，按需找到，轻松下载。**

用户不需要读仓库配置、辨认 Release 附件或记住版本号。页面仍提供最低系统要求、架构选择和获取方式；无法可靠判断时请用户选择，不猜测安装包。

“必备”分成三层：平台常用、场景精选、进阶工具。每种用途默认推荐一个工具，提供一到两个替代项。免费、开源、无需注册分别标记，不将三者混为一谈。

## 2. 当前基础与需要补齐的内容

- 现有 apps/windows、darwin、linux 均有分类清单；另有 Android、iOS、Android TV、Linux 掌机及多个游戏主机目录。
- tools/generate_catalog_html.py 当前只聚合三个电脑平台，生成根目录 catalog.html。
- 现有分类存在语义重叠：办公/办公与设计，多媒体/多媒体与设计/音视频，网络/网络与通讯/网络与协作等。
- 现有下载标记表示存在解析规则，并不等于下载链接已验证。网站应另设解析结果与检查状态。
- 保留现有 JSON 和命令行工具兼容性；增加展示元数据和归一化导出层。

## 3. 页面与导航

主导航：发现工具｜平台｜分类｜场景清单｜使用帮助。

首页自上而下：

1. 搜索框：“搜软件名称，或输入你想做的事”。
2. 当前平台提示和手动切换入口。
3. 平台常用精选：初始展示 8～12 个，不把全部工具堆到首页。
4. 分类入口：图标、名称、一句用途。
5. 场景清单：新电脑、办公学习、内容创作、开发、设备互传等。
6. 最近检查可用的工具；时间明确写“链接检查时间”或“版本获取时间”。
7. 关于来源、反馈问题、项目仓库。

平台页：平台介绍 → 常用精选 → 场景清单 → 分类浏览 → 全部软件。

分类页：解决什么问题 → 新手首选 → 替代工具 → 完整结果与筛选。

工具详情页：名称和图标 → 一句话用途 → 真实截图 → 适合谁 → 三条核心能力 → 主获取按钮 → 替代工具 → 系统要求、许可、来源和更新时间。

场景页：要完成的任务 → 每一步对应的工具 → 按需勾选收藏。第一版不承诺批量安装。

建议路径：/platform/windows/、/category/office/、/app/localsend/、/collections/new-pc/。每个工具共享一个详情页，内部切换平台，避免重复页面。

## 4. 平台规划

| 平台 | 常用内容优先级 | 获取体验 |
| --- | --- | --- |
| Windows | 解压、搜索、截图、办公、播放器、互传、备份 | 已确认架构时推荐稳定安装包；其他版本折叠展示 |
| macOS | 办公、文件处理、截图、播放器、互传、备份、效率 | 区分 Apple Silicon / Intel / Universal；不能只凭浏览器判断芯片 |
| Linux | 办公、媒体、开发、备份、互传 | 先选发行版或包格式，优先官方支持的安装方式 |
| Android | 互传、阅读、媒体、密码、文件、开源应用发现 | 官方 APK、官方商店或 F-Droid 分别标明；说明签名渠道不能随意混换 |
| iPhone / iPad | 互传、阅读、笔记、媒体、办公 | 默认官方 App Store；标明地区限制与 iPad 适配情况 |
| Android TV | 遥控友好播放器、媒体库、设备互传 | 只展示已确认电视适配的应用；与手机版区分 |
| Linux 掌机 | 启动器、串流、兼容工具、存档备份 | 区分桌面模式/游戏模式，写清适用设备和安装条件 |
| Switch、PS4、PS5、Vita、Xbox | 官方商店、配套工具、串流、存档管理资料 | 独立设备专区；兼容性按机型、系统和前置条件展示，无合适通用入口时提供说明 |

主机专区首版以经过核验的官方入口和配套工具为主；不强行将现有目录里的每个条目列为“必备”。商业游戏不作为普通软件安装包聚合。

## 6. 各平台“必备”清单模板

“必备”是编辑精选，不表示所有人都需要安装。同一能力如系统已满足，提示“可直接用系统自带”。

### Windows：新电脑常用 10 项能力

浏览器、解压、文件搜索、截图标注、办公/PDF、影音播放、设备互传、密码管理、备份、远程协助。开发、设计、AI 不强制加入基础清单。

第一批可核实基础：7-Zip、LibreOffice、VLC、LocalSend、KeePassXC；其余用途从现有清单选出一个首选和一个替代。

### macOS：日常效率 8 项能力

办公/PDF、媒体播放、设备互传、密码管理、备份、窗口管理、截图标注、文件归档。先介绍系统自带能力，再补第三方工具。不能为凑清单重复安装相同用途工具。

### Linux：桌面入门 8 项能力

软件安装入口、办公、媒体播放、互传、密码管理、备份、截图、设备联动。按 Debian/Ubuntu、Fedora 等安装生态展示；AppImage/Flatpak 等入口仅在项目实际提供时出现。

### Android：手机实用 8 项能力

跨设备互传、阅读、媒体、文件管理、密码管理、笔记、设备联动、开源应用发现。LocalSend 可作互传候选；F-Droid 作为开源应用发现入口。涉及后台权限、付费或配置要求写在简介旁。

### iPhone / iPad：手机与平板 6 项能力

跨设备互传、阅读、笔记、媒体、密码管理、文档处理。优先系统能力与官方商店，iPad 单列手写、分屏、键盘工作场景。不要将桌面软件同名条目直接视为移动端可用。

### Android TV：客厅常用 4 项能力

本地播放、家庭媒体库、局域网传输、遥控管理。候选如 VLC、Kodi、Jellyfin 客户端，上线前核实具体 TV 客户端和遥控支持。

### Linux 掌机与游戏设备：按任务给清单

掌机首次配置、电脑串流到掌机、控制器设置、存档备份分别成专题。游戏主机按设备独立说明，不共用“装机十大必备”。

## 7. 场景专题

首版：新电脑装好就用、办公学习、截图录课、手机电脑互传、文件备份、开发入门。

后续：自媒体创作、设计绘画、AI 入门、本地 AI、家庭影音、掌机串流。

每张专题卡写明结果，例如“把手机照片传到电脑”，而不是只写“网络工具”。进入后说明前置条件、需要几个工具、是否需要账号和付费。

## 8. 搜索与筛选

- 支持名称、中文别名、英文名、拼音首字母、用途关键词。
- “解压”“录屏”“传照片”“做流程图”等用途词映射到分类和工具标签；首版用可维护词典，不依赖在线 AI。
- 排序依次考虑名称精确匹配、别名、用途、简介；当前平台的已验证结果优先。
- 当前平台无结果时提供“查看其他平台”，不静默改变用户筛选。
- 筛选维度：平台、分类、免费/付费、开源、中文、安装包/商店/网页、是否需要账号。
- 同一产品合并展示，x64/ARM64/便携版放在版本选择中，不占多个搜索结果。
- 搜索空状态提供近义词、相关分类和提交收录入口。

## 10. 版本解析与更新

默认选择最新兼容稳定版；排除预发布、源码包、调试符号和错误架构。不能将 GitHub 的 latest 标签直接等同于每个平台都有可安装附件。

版本与链接在构建任务中集中解析，生成静态下载索引；页面不让每位访客直接调用 GitHub API，也不暴露令牌。

建议常用工具每 6 小时检查、完整目录每天检查；这是初始运维配置，按配额和上游限制调整。索引记录版本、来源、平台、架构、最低系统、获取时间、链接检查状态。

解析失败：保留最近成功记录并显示检查时间；超过容忍期撤下直接下载按钮，提供官方发布页。只有 HEAD/GET 可访问不代表安装验证成功，两种状态分开。

浏览器能推测操作系统，但不能可靠识别所有架构、发行版和设备兼容性。无法判断时用一个简短选择器；不要求用户自己辨认文件名。

Linux 优先维护安装方式与渠道；iOS 使用商店入口；网页工具使用“打开使用”；条件性设备工具使用“查看安装说明”。

本网站负责获取工具，不承诺给已安装软件静默更新。已有本地更新工具作为进阶入口，后续可增加“导出更新清单”。网站不自动执行下载文件。

## 11. 数据与构建方案

推荐在现有生成器基础上扩展静态站，不先引入账号系统或常驻服务器。需要即时动态解析时再评估轻量 API。

数据分三层：

1. 原始平台配置：继续供 lookup_app、auto_update 使用。
2. 展示元数据：产品统一 ID、别名、归一分类、用途标签、精选理由、图标、截图、官网与平台关联。
3. 自动生成索引：站点目录、搜索索引、解析后的版本与下载记录。

建议新增 site-content/categories.json、collections.json、products.json；导出 dist/site/。路径是实施建议，尚未创建。

同一产品的基础介绍共享，平台差异单独维护。分类重映射不直接批量重命名原始文件。构建校验产品 ID、引用关系、平台映射、重复条目和缺失来源。

## 12. 域名与发布

建议 tools.<已有主域名>，也可 apps.<已有主域名>。域名由用户提供后再设置 DNS。

先确认当前仓库 Pages 配置、访问目标地区和托管能力，再选择 GitHub Pages 或其他静态托管；绑定子域名、HTTPS 和唯一规范地址。国内外实际访问速度以测试为准。

软件安装包继续来自官方渠道；如果提供加速链接，应标明服务来源和原始下载备用入口，不宣传为官方镜像。暂不自行托管全部安装包。

## 13. 交付阶段与验收

### 第一阶段：可用的网站基础

上线首页、搜索、统一分类、三个电脑平台和 Android/iOS；首批约 40～60 个独立精选产品，跨平台共享产品信息。完整目录保留，但未核验条目不冒充精选。

完成标准：手机/电脑页面可用；每个平台有入门清单；精选产品均有介绍与官方入口；平台切换、用途搜索、来源标记正确；无架构误导；缺失下载可回退官网。

### 第二阶段：下载与维护闭环

完善定时解析、稳定版选择、失败回退、链接状态、详情截图、问题反馈；接入既有更新清单的导出能力。

完成标准：代表性的跨平台工具验证全流程；上游失败不产生错误链接；预发布、源码包和错误架构被排除；访问端不需要 GitHub 令牌。

### 第三阶段：设备与专题扩展

加入 Android TV、Linux 掌机、主机配套专区，丰富场景专题。每个设备入口先有完整介绍，再增加工具数量。

### 第四阶段：依据使用情况优化

观察搜索无结果比例、分类到详情点击、下载按钮点击、失效链接和平台分布。按钮点击仅表示获取意向，不等于下载完成或成功安装。无真实统计时不展示“热门排行”和虚构下载量。
